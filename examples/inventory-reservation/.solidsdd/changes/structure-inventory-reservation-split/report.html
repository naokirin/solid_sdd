ArchitecturePlan — 実施済

status: changed

Split the single reservation.ts module into an inventory module (stock ownership) and a reservation module (hold lifecycle), so future stock-related work (e.g. multi-warehouse) doesn't need to touch hold/TTL/authZ logic. Design-only: this repository's implementation intentionally stays a single file for now (see README "Out of scope").

Critique (architecture_plan) — pass

Two modules with clear, non-overlapping responsibilities. One directed dependency (reservation -> inventory) with a stated reason, and a forbid_dependency constraint on the reverse edge that matches the stated rationale (keep inventory reusable independent of hold/TTL/authZ). No responsibility, boundary, ownership, or checkability gaps.

  • minor architecture-plan.json#modules/1/public — ReservationService is a single facade; a narrower read-only lookup port could be split out later, but one facade is acceptable at standard density.

    checkable success; W5 elevates service-side TTL expiry so a hold past
    its TTL restores held quantity to available stock (no principal / AuthZ).

    not-visible lookup fails as named PreconditionError and unauthorized

    use the same named InsufficientStockError channel as sequential

    currently visible soft-holds as a JSON array of LookupResponse items

-- Source of truth for DbC; tests under tests/contracts are derived from this.
-- W1: authorized reserve soft-hold (PrincipalAuthorized, QuantityPositive,
--     SufficientAvailableStock, HoldCreatedWithTtl, AvailableStockReduced).
-- W2: insufficient-stock reserve failure is first-class — named
--     InsufficientStockError; no Hold created; available stock unchanged.
-- W3: unauthorized reserve or release fails with named UnauthorizedError;
--     no Hold created by the failed attempt; available stock and existing
--     holds unchanged.
-- W4: authorized release restores held quantity to available stock and
--     removes the hold (HoldExists, AvailableStockRestored, HoldRemoved).
-- W5: service-side expire past TTL restores held quantity and removes the
--     hold (HoldExists, HoldPastTtl, AvailableStockRestoredOnExpiry,
--     HoldRemoved); PreconditionError when hold missing or not past TTL.
-- add-reservation-lookup W1: authorized get-by-id lookup of an existing
--     visible soft-hold (PrincipalAuthorized, HoldExists, ResultIsHoldDetails,
--     AvailableStockUnchanged, HoldsUnchanged); no mutation.
-- add-reservation-lookup W2: named missing/not-visible (PreconditionError)
--     and unauthorized (UnauthorizedError) lookup failures; stock and holds
--     unchanged. Missing and not-visible share one PreconditionError channel.
-- add-lookup-available-stock W2: authorized lookup success includes current
--     availableStock for the hold's SKU (self.availableStock(hold.sku), not a
--     reserve-time snapshot); retain ResultIsHoldDetails hold fields and
--     AvailableStockUnchanged / HoldsUnchanged; UnauthorizedError /
--     PreconditionError failure posts unchanged (no mutation).

--     losers on contract-testable paths; AvailableStockNonNegative is a

-- Non-negative available stock for every tracked SKU (W1 foundation;
-- W2 sequential/contract-testable SoT bridge — no additive inv).
-- Concurrent interleaving exclusivity is formal-owned (W2 formal/).
context Reservation
inv AvailableStockNonNegative:

    self.availableStock(s) >= 0)

context Reservation::reserve(principal: String, sku: String, quantity: Integer, ttlSeconds: Integer): Hold

pre QuantityPositive: quantity > 0
pre SufficientAvailableStock: self.availableStock(sku) >= quantity
post HoldCreatedWithTtl: result.oclIsNew() and result.sku = sku and result.quantity = quantity

post AvailableStockReduced: self.availableStock(sku) = self.availableStock(sku)@pre - quantity
-- SufficientAvailableStock violation (sequential insufficient stock OR
-- concurrent race loser observing availableStock@pre < quantity) → named
-- domain error InsufficientStockError (same channel; not a language
-- builtin / not a concurrent-only error type); no extra soft-hold for the
-- failing attempt; available stock unchanged by that attempt.
-- W2 reuses these posts as the sequential/Vitest SoT stand-in (no new OCL).
post InsufficientStockError:
  (self.availableStock(sku)@pre < quantity) implies result.oclIsInvalid()
post NoHoldCreatedOnInsufficientStock:
  (self.availableStock(sku)@pre < quantity) implies self.holds() = self.holds()@pre
post AvailableStockUnchangedOnInsufficientStock:
  (self.availableStock(sku)@pre < quantity) implies
    self.availableStock(sku) = self.availableStock(sku)@pre

-- for the operated SKU (success and insufficient-stock / race-loser paths).

post AvailableStockNonNegativeAfterReserve:

--     (not a language builtin); no soft-hold; stock and holds unchanged.
-- W2 SoT bridge: AuthZ unchanged — opaque-principal UnauthorizedError posts.
post UnauthorizedErrorOnReserve:
  (not principal.isAuthorized()) implies result.oclIsInvalid()
post NoHoldCreatedOnUnauthorizedReserve:
  (not principal.isAuthorized()) implies self.holds() = self.holds()@pre
post AvailableStockUnchangedOnUnauthorizedReserve:
