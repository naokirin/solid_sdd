# Adapter policy

Initial adapters fixed for MVP, plus skeletons added in Phase 2. See each adapter README and the skills for detail.

## API: OpenAPI 3.x (default)

- **Artifact**: `openapi/openapi.yaml` (or the project’s equivalent path)
- **Role**: Contract for HTTP-boundary request/response shapes, errors, and compatibility
- **Verification**: `@redocly/cli lint … --extends=spec` (via PATH or `npx` when available) plus checks that the implementation matches the contract (contract tests or response validation). If Redocly is unavailable, lint is `skipped` (does not fail the whole run)

## API: GraphQL SDL (Phase 2)

- **Artifact**: `graphql/schema.graphql` (optional operations docs)
- **Role**: Boundary contract for GraphQL-first projects (OpenAPI alternative)
- **Verification**: Same as OpenAPI—`@redocly/cli lint … --extends=spec` when available; otherwise `skipped`
- **Evaluation sample**: [../examples/arithmetic-graphql](../examples/arithmetic-graphql)
- **Conventions**: [../adapters/graphql/README.md](../adapters/graphql/README.md)

## DbC: UML OCL → contract tests (subagent)

Does not depend on language-built-in contract features.

1. **First-class artifact written by humans / `solidsdd.apply.dbc`**: OCL (preconditions, postconditions, invariants)
2. **Dependent artifact generated by a subagent**: Test code derived from OCL
3. **Verification**: Contract compliance is judged from those test results

```text
OCL (source of truth)
        │
        ▼
  solidsdd.derive.tests (Subagent required)
        │
        ▼
  Contract test code ──solidsdd.verify (Subagent)──▶ pass / fail
```

Isolation rules when called from the orchestrator: [execution-model.md](execution-model.md).

OCL stays the source of truth; tests are regenerable dependents. The implementation language is a swappable “test generation target” in the adapter.

### Test generation target: Ruby / RSpec (Phase 2)

- **Artifact**: `spec/contracts/**/*_spec.rb`
- **Conventions**: [../adapters/ruby-rspec/README.md](../adapters/ruby-rspec/README.md)
- **Evaluation sample**: [../examples/arithmetic-ruby](../examples/arithmetic-ruby) (Calculator only)

Language-native contracts gems are **not required** (deferred / opt-in).

## Evaluation stacks

- **Default**: TypeScript (Node.js) + Vitest — [../examples/arithmetic-api](../examples/arithmetic-api) (OpenAPI), [../examples/arithmetic-graphql](../examples/arithmetic-graphql) (GraphQL)
- **Alternate test target**: Ruby + RSpec — [../examples/arithmetic-ruby](../examples/arithmetic-ruby)
- **Future candidate**: Full Rails app (today the RSpec target proves the alternate path)

## Evaluation scenario

Same domain (arithmetic + memory when needed), swapping only the API-boundary shape for comparison.
